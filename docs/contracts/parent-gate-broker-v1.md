# Durable parent-gate broker v1

Default off: `MEDIA_PARENT_GATE_ENABLED` must be explicitly true, with inbox and
producer journal enabled, configured `MEDIA_PARENT_GATE_URL` ending exactly in
`/admin/api/b2-parent-gate/` and separate `MEDIA_PARENT_GATE_TOKEN`. The token
corresponds to the edge-only `b2_storage_coordination_token` logical binding;
worker/intake credentials cannot substitute. No credential is created here.
HTTPS only, fresh HTTP/1 connections without an idle pool, no URL
credentials/query/fragment, redirects/proxy discovery disabled,
three-second total network deadline and8KiB maximum response. No raw network or
provider error, credential or policy payload is returned/logged.

Worker-authenticated bounded POST routes, under existing32KiB/ten-second limits:

- `/internal/media-processing/attempts/gate/claim`: `{lease,attempt_id}`.
- `/internal/media-processing/attempts/gate/inspect`: `{attempt_id}`.

The immutable planned attempt supplies parent and purpose `existing_family`.
Workers cannot choose original-write admission, parent, edge URL, gate generation,
owner hint or `gate_held`. Original-write admission remains unavailable until its
actual authenticated upload-intent hook exists.

Before mutation HTTP, the broker locks the job identity and evaluates current
lease/revision/deadline after locking, then commits an exact `gate_claim_request`
in existing `media_storage_attempts`. Only the transaction winning its null-to-
request transition sends HTTP. The request is never replaced or cleared, including
after timeout, restart, new lease, release, or any number of intermediate owners.
Replays return retained history, not another claim. Preflight inspect is read-only;
its missing/released observation cannot itself authorize provider effects.

Migration005 adds request, outcome and observation JSON fields with bounded shape
constraints to the existing attempt table. No second database/service/outbox is
introduced. Request commit precedes HTTP; response persistence follows separately
and may occur after lease expiry. Crash/cancellation between them retains an issued
request with unknown outcome. Timeout stores `state:unknown`. A successful typed
readback is an observation only. Reconciliation stores exact current observation
separately without replacing the historical mutation outcome.

Every receipt has `dispatch_available:false`. There is no worker release endpoint,
release request generated by this client, or automatic release on lease expiry.
Existing dispatch remains unavailable and journal mode still rejects new legacy
completion while preserving committed exact completion replay. A gate/plan is not
current-source, policy, artifact receipt or completion authority.

Next integrated producer stage must prove configured current source equals the
exact assignment, pinned checksum/probe, uncached policy/rechecks and participation
of ALL original writers in the same shared exclusion. Then per-object one-shot
dispatch and positively verified pinned receipts must establish bounded writer
quiescence before release. A receipt or process timeout alone is not quiescence.
Missing settlement keeps the gate unavailable/pending, never TTL-cleared.

Real PostgreSQL two-connection and loopback HTTP tests cover commit-before-send,
one-shot concurrency, accepted request/response loss, historical uncertainty,
retained readback through an independent database connection and resurrection
prevention after intermediate owners. An actual service-process kill/restart
drill remains integration acceptance, not a test performed by this source stage. CI uses
an explicitly disposable PostgreSQL database. Skips without that database are
not durability proof. Real provider/erasure/performance acceptance remains root-owned.
